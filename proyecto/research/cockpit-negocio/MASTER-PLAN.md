# Master Plan — Cockpit como herramienta de negocio

## Decisiones del operador (firmes)
1. **chris-corp** = un **sistema** (el Odoo compartido, usado por todas las empresas pero sistema en sí). → repo en GitHub (`alpacapurpura/chris-corp`), CLAUDE + scaffold de desarrollo con el **starter `odoo-v19`**, instrumentado para desarrollarse **desde el cockpit**.
2. **Prenter** = **carpeta/repo nuevo** (`alpacapurpura/prenter`). `alpaca-harness` es **un sistema** de Prenter; el cockpit de Prenter debe mostrar **la evolución de alpaca-harness** (board/roadmap del factory).
3. **Multi-sesión:** una fase por conversación; carpeta de campaña acumula aprendizaje; al cerrar cada fase, entregar el prompt de la siguiente.

## Principio rector
El Cockpit deja de ser solo SDD (stories/board) y pasa a **monitor de negocio**: Empresa → Sistema → (procesos · objetivos · gaps). Un sistema sin backlog de software (Odoo) **se ve igual** — un nodo vacío es un gap de digitalización, no algo a ocultar. Engancha con la visión original (NODOS, M1 levantamiento, procesos/personas/sistemas vs objetivos).
